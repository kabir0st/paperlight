# Chrome Web Store listing assets

Generated by `node tools/store-assets.mjs`. Every file is 24-bit PNG with no
alpha channel, at the exact canvas the store requires. The script verifies both
before it exits, so if it prints `All files meet the Chrome Web Store
requirements` the uploads will be accepted.

| File | Slot | Canvas |
|---|---|---|
| `screenshot-1-dark.png` | Screenshot 1 | 1280x800 |
| `screenshot-2-themes.png` | Screenshot 2 | 1280x800 |
| `screenshot-3-popup.png` | Screenshot 3 | 1280x800 |
| `screenshot-4-readaloud.png` | Screenshot 4 | 1280x800 |
| `screenshot-5-privacy.png` | Screenshot 5 | 1280x800 |
| `promo-small.png` | Small promo tile | 440x280 |
| `promo-marquee.png` | Marquee promo tile | 1400x560 |

Screenshots are uploaded in order, and the first is the one people actually see,
so keep `screenshot-1-dark.png` first unless you are testing something.

## The rest of the listing

Fields the store asks for that are not images:

- **Name** comes from `manifest.json`: `Paperlight: PDF Dark Mode & Read Aloud`
- **Short description** (132 char limit) comes from the manifest `description`:
  *Dark mode, sepia, and paper themes for Chrome's PDF viewer, plus read PDFs
  aloud with natural offline voices.* (109 characters)
- **Category**: Accessibility, or Productivity/Tools
- **Privacy policy URL**: there is no manifest field for this. Paste
  `https://github.com/kabir0st/paperlight/blob/HEAD/PRIVACY.md` into the
  Privacy practices tab.
- **Data disclosures**: [PRIVACY.md](../PRIVACY.md) lists the answers. Every
  collection category is *no*, and nothing is sold or transferred.
- **Permission justifications**: the store asks for one per permission. The
  table in [PRIVACY.md](../PRIVACY.md) is written to be pasted in, especially
  the `<all_urls>` one, which is the permission most likely to be queried.

## Regenerating

```bash
npm install --no-save puppeteer-core
node tools/capture-screenshots.mjs path/to/document.pdf   # source images first
node tools/store-assets.mjs                               # then the compositions
```

The store assets composite the PNGs from `docs/screenshots/`, so regenerate
those first if the UI has changed.

## Known gap: the icon

`images/icon*.png` is still a banana, left over from the extension's former name
(Banana-Gentle-PDF). Nothing in `store/` uses it, and these assets use a
stacked-paper mark built from the popup's own theme swatches instead. The
toolbar icon and the store's 128x128 icon still need replacing, or the listing
will keep showing a banana next to a product called Paperlight.

The listing slug is also still `banana-gentle-pdf-color-c`. Links resolve by
extension id regardless of slug, so nothing is broken, but the URL contradicts
the branding until the listing is renamed in the developer dashboard.
